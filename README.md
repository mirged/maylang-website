# maylang-website

The Maylang website: a static site generated by `maysite`, a generator written
in Maylang.

The design is in [DESIGN.md](DESIGN.md). This repository currently implements
the Phase 1/2 foundation: the workspace, the Markdown pipeline, the design
tokens, page layout, imported documentation, the standard-library reference,
search index, sitemap, feed and output checks. The Phase 1 findings and
timings are in [docs/spike.md](docs/spike.md).

## Requirements

- Linux x86-64 (including x86-64 WSL 2)
- a released `mayc` (0.15.0 is the current target)
- a Maylang checkout at the tag in `site.json`, by default `../maylang`

`MAYLANG_SRC` overrides the checkout path. `MAYC` overrides the compiler used
for the build stamp and sample verification. If `MAYC` is unset and
`$MAYLANG_SRC/compiler/mayc/mayc_new` exists, that compiler is used; otherwise
the build falls back to `mayc` on `PATH`.

## Build

```sh
mayc main.may -o maysite
./maysite build          # writes build/site/
./maysite check          # builds, then checks structure and links
./maysite serve 8000     # builds, then serves http://127.0.0.1:8000/
```

`maysite` is the binary in this directory, so invoke it as `./maysite`, not
`maysite`, unless you add the directory to `PATH`. The first build after a
source change takes about a minute; later builds reuse the page cache and start
in a few seconds. With `make`:

```sh
make serve
```

If `./maysite` is missing, build it first (`mayc main.may -o maysite`). If
`./maysite serve 8000` reports that the port is busy, use another port, for
example `./maysite serve 8001`.

Do not open `build/site/index.html` with `file://`. The generated pages use
root-relative URLs such as `/assets/site.<hash>.css`, so a static file opened
directly will not load its stylesheet, scripts or navigation. Serve the
directory over HTTP; `maysite serve` is the local command, and
`python3 -m http.server --directory build/site` works too.

Or use the workspace:

```sh
may build
may run -- build
may test
```

The output is static HTML, CSS and JavaScript. There is no server-side code.

Rendered pages are cached in `.may/render/` by a fingerprint of the page, the
templates, `site.json`, the assets and the generator sources. A first build
takes about a minute; an unchanged rebuild takes about two seconds.

## Layout

```
main.may                 CLI entry: build | check | version
src/
  build.may              page collection, jobs, child rendering, output
  config.may             site.json and front matter
  markdown.may           Markdown subset to HTML, including the list-only transform
  highlight.may          static syntax highlighting
  stdlib.may             inventory.json/descriptions.json to module pages
  templates.may          layout fragments and navigation
  links.may              repository-to-site link rewriting
  checks.may             output structure, links, anchors and byte checks
  search.may             search-index.json
  jsonlite.may           incremental reader for the large reference JSON
  fs.may, html.may, util.may, assets.may
content/                 site-only prose
templates/               HTML fragments with ${slot}s
assets/                  one stylesheet, three small scripts, favicon
tests/                   *.test.may
site.json                release, navigation, imports and source pin
```

## Notes

- Pages render in child processes. The full runtime's collector becomes slow
  under long single-process allocation runs (the risk recorded in DESIGN.md),
  and one process per page keeps builds reliable. This is a deliberate
  Phase 1 mitigation, not a permanent architecture.
- The reference inventory and descriptions are read incrementally rather than
  with one `json_parse`, for the same reason.
- `build/` and `.may/` are generated and ignored.
